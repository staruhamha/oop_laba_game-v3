Логическое разделение классов

Цель работы

Расширить игровую систему из предыдущих лабораторных работ, добавив управление строительством зданий, производством юнитов, ресурсами и исследованиями. Реализовать взаимодействие между игровыми подсистемами с использованием паттернов проектирования Facade, Mediator, Chain of Responsibility и Command.

Язык реализации - C++.

Основные требования к программе

1. Управление базой (Base). Хранение характеристик базы, ресурсов, юнитов и построенных зданий.
2. Управление юнитами (UnitManager). Создание юнитов через существующие фабрики, перемещение по карте и проверка занятости клеток.
3. Управление зданиями (BuildingManager). Строительство зданий, проверка условий строительства и производство юнитов через казармы.
4. Управление ресурсами (MaterialsSystem). Сбор ресурсов с точек, хранение общего количества ресурсов и их распределение между юнитами и зданиями.
5. Боевая система (CombatSystem). Реализация атак между юнитами с учётом характеристик атаки и защиты.
6. Исследования. Реализация системы исследований, позволяющей улучшать характеристики и производство.
7. Обработка команд. Создание системы обработки пользовательского ввода и проверка правильности команд и их аргументов.
8. Управление игрой (GameFacade и GameMediator). Организация взаимодействия между игровыми подсистемами и предоставление общего интерфейса для управления игрой.
9. Журнал команд. Запись введённых команд и результатов их выполнения.
10. Тестирование. Проверка основных функций программы и демонстрация игровых сценариев.

Архитектура программы

Программа построена на основе объектно-ориентированного подхода. Основные игровые компоненты разделены на отдельные классы и подсистемы.

Класс GameFacade предоставляет общий интерфейс для работы с игрой и обработки пользовательских команд. Он объединяет основные компоненты программы и передаёт запросы соответствующим обработчикам.
Класс GameMediator отвечает за взаимодействие между подсистемами. Через него выполняются операции создания и перемещения юнитов, строительство зданий, распределение ресурсов, исследования и боевые действия.
Класс Base хранит состояние базы, информацию о юнитах и зданиях, а также основные характеристики и ресурсы.
Класс UnitManager отвечает за создание и перемещение юнитов. Для создания используются фабрики из предыдущей лабораторной работы.
Класс BuildingManager управляет зданиями, проверяет возможность строительства и отвечает за производство юнитов.
Класс MaterialsSystem отвечает за сбор и распределение ресурсов. В игре используются дерево, металл и энергия.
Класс CombatSystem отвечает за проведение атак и расчёт урона.
Для хранения информации о местности используется TerrainMap. При перемещении юнитов проверяется проходимость клеток и учитываются особенности ландшафта.
Для обработки пользовательских команд используются отдельные классы обработчиков. После ввода команда передаётся по цепочке до подходящего обработчика.

Реализация паттернов проектирования

Фасад (Facade) - реализован в классе GameFacade. Он предоставляет единый интерфейс для взаимодействия с игровыми подсистемами и скрывает особенности их внутренней работы.
Посредник (Mediator) - реализован в классе GameMediator. Он координирует взаимодействие между базой, менеджерами юнитов и зданий, системой ресурсов и боевой системой.
Цепочка обязанностей (Chain of Responsibility) - используется для обработки пользовательских команд. Каждая команда передаётся обработчикам, которые проверяют её тип и при необходимости передают следующему обработчику.
Команда (Command) - используется для представления игровых действий в виде отдельных объектов. Команды содержат необходимые параметры и позволяют отдельно обрабатывать различные действия игрока. Также реализована история команд.
Итератор (Iterator) - используется в классе GameFieldIterator для последовательного обхода юнитов игрового поля без необходимости напрямую работать с внутренним контейнером.

Результаты тестирования

В ходе проверки программы были протестированы основные игровые действия.
Проверено создание юнитов разных типов, их характеристики и расположение на карте. Также проверено перемещение юнитов с учётом границ карты и особенностей местности.
При проверке строительства зданий успешно построилась казарма. Повторное строительство на занятой клетке было отклонено. Также проверена ситуация, когда клетка занята юнитом, и попытка строительства за пределами карты.
Проверено производство юнитов через казармы. Были созданы юниты типов Infantry, Marksman, Specialist и JetpackUnit. При недостаточном количестве ресурсов производство не выполняется.
Проверена работа системы ресурсов, боевых действий, восстановления здоровья и исследований.
Также проверена обработка пользовательских команд. При вводе неправильных аргументов программа сообщает об ошибке, а неизвестные команды не передаются на выполнение.
Отдельно проверена работа журнала команд. Он правильно различает успешно выполненные команды, команды с отказом и неизвестные команды.

Примеры команд

Для управления игрой используется ввод текстовых команд в консоль.

Создание юнитов:
create unit infantry at 5,5

Создаёт юнита типа Infantry на координатах X=5, Y=5.

Перемещение юнитов:
move unit 1 to 2,3

Перемещает юнита с ID 1 на координаты X=2, Y=3.

Атака:
attack unit 1 target 2

Юнит с ID 1 атакует юнита с ID 2.

Сбор ресурсов:
collect unit 1 from 1

Юнит с ID 1 собирает ресурсы из точки с ID 1.

Строительство зданий:
build barracks at 3,3

Строит казарму на координатах X=3, Y=3.

В качестве типа здания также могут использоваться PowerPlant, Laboratory, Warehouse и Hospital.

Производство юнитов:
produce Specialist in 1

Производит юнита типа Specialist в казарме с ID 1.

Доступные типы юнитов: Infantry, Marksman, Specialist, JetpackUnit.

Исследования:
research attack_upgrade

Запускает исследование улучшения оружия. Также доступны defense_upgrade и production_upgrade.

Распределение ресурсов:
distribute wood 50 to 1

Передаёт 50 единиц дерева юниту с ID 1.

Для распределения ресурсов зданиям используется указание типа здания вместо ID.

Просмотр характеристик:

stats units - информация о юнитах.
stats buildings - информация о зданиях.
stats resources - информация о ресурсах.
stats log - просмотр журнала команд.

Обозначения и правила ввода

ID - уникальный номер юнита, здания или точки ресурсов.
X, Y - координаты объекта на карте.
amount - количество передаваемых ресурсов.
unitType - тип создаваемого юнита.
buildingType - тип здания.

Названия типов юнитов и зданий вводятся в соответствии с поддерживаемыми программой значениями. Координаты указываются через запятую, а параметры команд разделяются пробелами.
